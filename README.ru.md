# Servarr Tools UI

Автономная, преимущественно предназначенная для чтения панель управления и backend-for-frontend (BFF) для Rollarr, Torrent Name Normalizer и Sonarr Auto-add. Использует только стандартную библиотеку Python и статические CSS/JavaScript; отсутствуют этап сборки фронтенда и установка зависимостей во время выполнения.

[Полная английская версия / Full English README](README.md)

## Установка

Образ контейнера: `ghcr.io/vladido/servarr-tools-ui:latest` ([GHCR](https://github.com/vladido/servarr-tools-ui/pkgs/container/servarr-tools-ui)).

Для фиксированной версии закрепите доступный тег `sha-<commit>` или digest; перед обновлением сохраните предыдущий digest.

Создайте отдельный каталог установки и сохраните следующий YAML как `compose.yaml` (полный пример из [compose.example.yml](compose.example.yml)):

```yaml
services:
  servarr-tools-ui:
    image: ghcr.io/vladido/servarr-tools-ui:latest
    restart: unless-stopped
    environment:
      ROLLARR_URL: http://rollarr-controller:8080
      NORMALIZER_URL: http://torrent-name-normalizer:8077
      AUTO_ADD_URL: http://sonarr-series-auto-add:8078
      SONARR_URL: http://sonarr:8989
      SONARR_API_KEY: ${SONARR_API_KEY:?set SONARR_API_KEY}
      SERVARR_TOOLS_TOKEN: ${SERVARR_TOOLS_TOKEN:?set SERVARR_TOOLS_TOKEN}
      SERVARR_TOOLS_ALLOWED_HOSTS: ${SERVARR_TOOLS_ALLOWED_HOSTS:-localhost:8787,127.0.0.1:8787}
      UPSTREAM_TIMEOUT_SECONDS: "2"
    ports:
      - "127.0.0.1:8787:8080"
    networks:
      - servarr
    read_only: true
    tmpfs:
      - /tmp:size=16m,mode=1777
    cap_drop:
      - ALL
    security_opt:
      - no-new-privileges:true

networks:
  servarr:
    external: true
    name: ${SERVARR_NETWORK:-servarr}
```

Нужны Docker с Compose, Sonarr и три движка с API v1 на общей внешней сети `servarr`. Сеть должна существовать; при необходимости создайте её `docker network create servarr` и подключите зависимости. Другое имя задайте `SERVARR_NETWORK` в `.env` Compose. Панель не создаёт и не запускает движки.

Создайте `.env` в каталоге установки с правами `0600`, заменив значения своими:

```dotenv
SONARR_API_KEY=replace-with-sonarr-api-key
SERVARR_TOOLS_TOKEN=replace-with-shared-random-ascii-token
```

Задайте такой же `SERVARR_TOOLS_TOKEN` в защищённых env-файлах всех движков и пересоздайте их для применения настройки. `.env` здесь используется Compose для подстановки `${...}`, а не как `env_file` контейнера. Встроенного входа пользователей нет: токен защищает обращения к движкам, но не браузерный доступ. Порт опубликован только на `127.0.0.1:8787`; для удалённого доступа используйте reverse proxy с внешней аутентификацией, сохранением `Host` и точным `SERVARR_TOOLS_ALLOWED_HOSTS`. Порты движков не публикуйте.

```sh
chmod 600 .env
docker compose config --quiet
docker compose pull
docker compose up -d
```

Откройте `http://127.0.0.1:8787/`. Контейнер работает от UID/GID `10001:10001`, не хранит собственное состояние, не монтирует Docker socket и не требует каталога для записи.

## Интерфейс и работа оператора



1. Панель по умолчанию открывается на английском. Выберите **Русский** или **English** в меню **Language / Язык**; выбор сохраняется в браузере.
2. Проверьте для каждого сервиса режим, последнюю ошибку и время **последнего успешного цикла**. Здоровье панели и здоровье движка — разные проверки.
3. Просмотрите **Последние полезные действия** и **Последние события**. Обычные `skipped` не означают поломку; причина объясняет, какая проверка не разрешила действие.
4. Кнопка **Запустить сейчас / Run now** ставит один цикл выбранного движка в очередь. Она не переключает dry-run/live и в live может привести к разрешённым движком изменениям qBittorrent/Sonarr. Не нажимайте её для простой проверки доступности.
5. Если один движок недоступен, проверьте его API и конфигурацию: остальные карточки продолжают работать. Панель не управляет контейнерами, не меняет настройки и не выполняет собственный импорт.

## Поведение

- Рендерит карточки сервисов и недавние строки аудита на сервере, затем опрашивает BFF того же источника (same-origin) для их обновления.
- Показывает производное состояние здоровья (health), режим dry-run/live, булевы флаги running/queued, структурированный последний запуск, последний успешный цикл, до пяти недавних полезных действий на сервис с опциональными миниатюрами постеров Sonarr, последнюю ошибку, скалярную сводку (summary) и доступность немедленного запуска.
- Нормализует метки времени ISO и Unix в RFC 3339 и позволяет браузеру локализовать отображаемые даты, время и округлённые длительности с помощью `Intl`.
- Обрабатывает каждый движок независимо: таймаут, некорректный ответ или недоступность деградируют только соответствующую карточку/источник аудита.
- Объединяет поля аудита из разрешённого списка (`service`, `timestamp`, `status`, `reason`, `subject`) и отображает весь текст от вышестоящих сервисов как текст, никогда как небезопасный HTML.
- Включает **Run now** только тогда, когда текущая возможность `/v1/status` выбранного движка это разрешает.
- Отклоняет запросы, у которых точное значение HTTP-заголовка `Host` не сконфигурировано, ещё до обращения к какому-либо движку.

Браузер обращается только к `/api/*` этого приложения. URL-адреса движков и Sonarr, bearer-токен и API-ключ Sonarr остаются на стороне сервера. Изображения постеров загружаются через `/api/posters/{series_id}` из фиксированной конфигурации Sonarr: BFF считывает метаданные сериала, принимает только его относительный путь постера `/MediaCover/`, преобразует этот проверенный путь в аутентифицированный маршрут Sonarr `/api/v3/mediacover/`, отклоняет редиректы, ограничивает размер обоих ответов и отдаёт только JPEG, PNG или WebP с заголовком `Cache-Control: no-store`. Неудачный или отсутствующий постер оставляет нейтральную заглушку фиксированного размера, не влияя на список действий. Немедленный запуск (run-now) требует специального заголовка запроса, отправляемого только с того же источника (кросс-сайтовые отправки форм отклоняются), сопоставляет слаг сервиса с фиксированной конфигурацией, повторно проверяет возможность запуска, отбрасывает любое тело запроса от браузера и заголовки авторизации/идемпотентности, а затем отправляет ровно `{}` настроенному движку вместе с серверным токеном и серверно-сгенерированным ключом идемпотентности.

## Контракт движка

Каждый настроенный движок должен предоставлять:

- `GET /v1/status`
- `GET /v1/audit?limit=N`
- `POST /v1/runs`

BFF передаёт серверный `SERVARR_TOOLS_TOKEN` в заголовке `Authorization` со схемой Bearer при вызове всех трёх конечных точек. Он принимает `capabilities.run_now` у Rollarr и верхнеуровневый `run_now` у Normalizer/Auto-add, требует, чтобы `queued` было булевым значением JSON, нормализует развёрнутый объект `last_run` в структурированные поля и извлекает его скалярную `summary`. Опциональное поле `last_success_at` сохраняется независимо от неудачного последнего запуска; при его отсутствии используется успешное `last_run.finished_at`. Состояние здоровья определяется как `degraded`, если присутствует ошибка последнего запуска, `last_error` или `error_class`, и как `healthy` в противном случае; сетевые и схемные ошибки остаются `unavailable`.

Ответы аудита используют канонический ключ `records` (устаревший `items` по-прежнему принимается). BFF независимо получает до 200 строк от каждого сервиса, нормализует `at`/`timestamp`, `event`/`status` и `reason`, и выводит до пяти новейших полезных действий на основе специфичных для сервиса разрешённых списков событий. Субъекты (subjects) собираются только из ограниченных значений `subject`, `old_name`, `new_name`, `candidate_title` и точных положительных целочисленных значений `series_id`; последнее отдельно раскрывается только для формирования маршрута постеров того же источника. Значения, содержащие URL, и все прочие поля от вышестоящих сервисов — включая хеши и секреты — исключаются. Ответы ограничены 256 КиБ, а схема/поля разрешены только из allowlist. Таймаут обращения к вышестоящим сервисам настраивается только в диапазоне 0,1–5 секунд и по умолчанию равен 2 секундам.

## Конфигурация

Все значения фиксируются при старте процесса:

| Переменная | Обязательна | Значение |
|---|---:|---|
| `ROLLARR_URL` | да | Абсолютный базовый URL HTTP(S) |
| `NORMALIZER_URL` | да | Абсолютный базовый URL HTTP(S) |
| `AUTO_ADD_URL` | да | Абсолютный базовый URL HTTP(S) |
| `SONARR_URL` | да | Абсолютный базовый URL HTTP(S) Sonarr, используемый только прокси постеров BFF |
| `SONARR_API_KEY` | да | API-ключ Sonarr, используемый только на сервере |
| `SERVARR_TOOLS_TOKEN` | да | Общий серверный bearer-токен |
| `SERVARR_TOOLS_ALLOWED_HOSTS` | нет | Список точных значений HTTP `Host` через запятую; по умолчанию `localhost:8787,127.0.0.1:8787` |
| `UPSTREAM_TIMEOUT_SECONDS` | нет | Таймаут на запрос, по умолчанию `2` |
| `LISTEN_HOST` | нет | Адрес привязки, по умолчанию `0.0.0.0` |
| `LISTEN_PORT` | нет | Порт прослушивания, по умолчанию `8080` |

URL-адреса со встроенными учётными данными и не-HTTP схемами отклоняются. Разрешённые хосты должны быть корректными именами хостов, адресами IPv4 или адресами IPv6 в квадратных скобках, каждый с опциональным портом. Маски (wildcards), схемы, пути и некорректные порты отклоняются при старте. Сопоставление использует только HTTP-заголовок `Host`; `X-Forwarded-Host` не доверяется. Приложение не отдаёт заголовки CORS, поэтому доступ к движкам из браузера не включён.

Обратные прокси должны добавлять публичный хост панели (включая публичный порт, если браузер его отправляет) в `SERVARR_TOOLS_ALLOWED_HOSTS`. Например, используйте `SERVARR_TOOLS_ALLOWED_HOSTS=tools.example.com` для развёртывания HTTPS на порту по умолчанию. Сохраняйте исходный заголовок `Host` при проксировании.

## Конечные точки BFF

- `GET /` — панель, отрендеренная на сервере
- `GET /api/status` — независимо агрегированная карта состояний
- `GET /api/audit?limit=25` — объединённые строки аудита, новые сначала (`1..100`)
- `GET /api/posters/{positive-series-id}` — прокси постеров Sonarr без кэширования, с фиксированной целью
- `POST /api/services/{rollarr|normalizer|auto-add}/runs` — запуск с фиксированной целью, защищённый проверкой возможности
- `GET /healthz` — локальная проверка живости/счётчик конфигурации

Все ответы JSON API используют `Cache-Control: no-store`. Заголовки безопасности ограничивают доступ к скриптам, стилям и сети тем же источником (same origin).

## Доступ, диагностика и обновление

Встроенного пользовательского входа нет. Серверный токен защищает обращение BFF к движкам, но не является паролем браузера. Пример Compose публикует только `127.0.0.1:8787`; при публикации через reverse proxy настройте внешнюю аутентификацию и нужный `Host` в allowlist. Engine API не публикуйте наружу.

```sh
curl http://127.0.0.1:8787/healthz
curl http://127.0.0.1:8787/api/status
```

- `Host` отклонён: сверяйте точный hostname и порт браузера с `SERVARR_TOOLS_ALLOWED_HOSTS`, сохраняйте исходный `Host` на proxy.
- `unavailable`: проверьте URL, внутреннюю сеть, таймаут и поддержку `/v1/status`/`/v1/audit` выбранным образом движка.
- `degraded`: последний цикл завершился ошибкой; смотрите движок, а не только `/healthz` панели.
- Кнопка недоступна: проверьте `run_now` движка и общий токен. Повторные/занятые запуски могут возвращать `409`.
- Нет постера: проверьте Sonarr и его API-ключ; список действий работает и без изображения.

Обновление: `docker compose pull`, затем `docker compose up -d`; после этого проверьте `/healthz`, все три карточки и аудит без запуска live-цикла вручную. Панель не хранит собственное долговременное состояние; для восстановления нужны Compose, защищённые env/secrets и настройки reverse proxy. Для отката закрепите предыдущий тег/дайджест образа.

## Для разработчиков: необязательная сборка из исходников

Для разработки с Git и Docker соберите локальный образ и задайте `image` в локальной копии Compose как `servarr-tools-ui:dev`. Требования к конфигурации, секретам и сети из предыдущих разделов действуют и при разработке.

```sh
git clone https://github.com/vladido/servarr-tools-ui.git
cd servarr-tools-ui
docker build -t servarr-tools-ui:dev .
```

### Локальный запуск

```sh
export ROLLARR_URL=http://127.0.0.1:8101
export NORMALIZER_URL=http://127.0.0.1:8102
export AUTO_ADD_URL=http://127.0.0.1:8103
export SONARR_URL=http://127.0.0.1:8989
export SONARR_API_KEY='replace-me'
export SERVARR_TOOLS_TOKEN='replace-me'
export SERVARR_TOOLS_ALLOWED_HOSTS=127.0.0.1:8080
export LISTEN_HOST=127.0.0.1
python3 -m servarr_ui.server
```

Откройте `http://127.0.0.1:8080/`. Проверка живости доступна по адресу `GET /healthz`; она намеренно не зависит от доступности движков.
